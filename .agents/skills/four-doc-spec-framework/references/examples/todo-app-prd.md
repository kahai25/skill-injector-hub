# Example: PRD for a simple todo app

**One-line pitch:** A keyboard-first todo app for developers who live in the terminal.

## Target user
- Primary: developers who already use Vim / VSCode keybindings all day
- Painful current workflow: switching to a mouse-driven app breaks flow
- Why existing tools don't cut it: Todoist, Things, TickTick all assume mouse-first UI

## What this app IS
- Add / complete / delete todos entirely by keyboard
- Group todos by project (single-level, no nested folders)
- Sync across devices for one signed-in user

## What this app is NOT
- Not a team collaboration tool. Single-user only in v1.
- No calendar view, no Gantt chart, no time tracking.
- No mobile app in v1 — responsive web only.
- No integrations (Slack, GitHub, Linear) in v1.
- No AI "suggestions" or "priority scoring" in v1.
- No offline mode in v1.

## Success looks like
- User adds their first todo within 10 seconds of signup, without touching the mouse.
- 80% of active users have >20 todos after week 1.

## Out-of-scope questions (parked)
- Should we support markdown in todo text? (parked — v2)
- Recurring todos? (parked — v2)
- Sharing a project read-only? (parked — v2)
